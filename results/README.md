# Results

All files here are generated by the scripts. Rerun them to reproduce (seeds are fixed). The VeloxQ rows
come from a cloud service that takes no seed, so they vary slightly between runs. Without a
`VELOX_TOKEN` they are left out.

| folder / file | produced by | content |
|---|---|---|
| `baseline/report.md`, `report.json` | `python run_baseline.py --veloxq` | Stage 1: QUBO sizes (incl. the job-order code, fewest qubits, comparison only), ground-state certificates, QAOA convergence, solver cross-checks (SA, tabu, VeloxQ) |
| `baseline/gantt_2x2.png`, `gantt_3x3.png` | `run_baseline.py` | Gantt charts of the delivered schedules |
| `extension/reduction.md` (+ `.json`, `.png`) | `python run_extension.py reduction` | qubit reduction and price of realism along the feature ladder, horizon effect |
| `extension/algorithms.md` | `run_extension.py algorithms --veloxq` | XY-QAOA variants, parameter transfer, SA / tabu / VeloxQ on four formulations, penalty sweep |
| `extension/scaling.md` | `run_extension.py scaling` | random extended instances with 2-6 jobs: qubits vs size, success vs qubits |
| `extension/disruption.md` | `run_extension.py disruption --veloxq` | 36 breakdown scenarios: right-shift vs QUBO re-plan (SA, XY-QAOA, live VeloxQ) vs CP-SAT |
| `extension/investment.md` | `run_extension.py investment` | one vs two milling machines on 40 order books |
| `extension/veloxq.md` (+ `.json`, `.png`) | `run_extension.py veloxq` (needs `VELOX_TOKEN`) | VeloxQ at scale: one call on the whole QUBO of 4-12-job order books (77-726 qubits), solver settings, decomposition with 8 sub-QUBOs per VeloxQ call vs SA |
| `extension/pce.md` (+ `.json`) | `run_extension.py pce` | Part 7: the certified domain-wall QUBOs of both baseline instances with Pauli correlation encoding on the fewest qubits (A: 8 variables on 2, B: 24 on 4), vs the untrained circuit, the same loss without a quantum state and SA |
| `extension/gantt_*.png`, `schedule_*.json`, `residual_*.json` | `run_extension.py` | example schedules and instances |

The two mandatory schedule files are in the repository root: `schedule_2x2.json`, `schedule_3x3.json`.
